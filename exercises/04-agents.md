# Stage 04 - Test Agents: planner, generator, healer

This branch adds the official Playwright Test Agents, generated by
`npx playwright init-agents` for **both** loops:

- Claude Code: `.claude/agents/playwright-test-{planner,generator,healer}.md`
- OpenCode: `.opencode/prompts/` + subagent wiring in `opencode.json`

Their engine is the second MCP server, **`playwright-test`**
(`npx playwright run-test-mcp-server`), now registered alongside the general
`playwright` server. Read [`MCP_SERVERS.md`](../MCP_SERVERS.md) before you
start - the two servers share tool names but behave differently, and the test
server needs `planner_setup_page` before any browser call.

Anchor points the agents rely on:

- `tests/seed.spec.ts` - an **active, empty** test the planner/generator attach
  to. Keep it active, keep it empty, never edit it.
- `specs/` - where the planner writes Markdown test plans.

Solution branch: `04-pw-agents-solution`.

> **Heads-up: this branch ships red on purpose.** One checkout spec fails
> because we simulated an app change that broke a locator (see exercise 3).
> That failure is the healer's raw material - do not fix it by hand.

## 1 · Plan

In OpenCode invoke the subagent with `@`; in Claude Code just ask for it by
name:

> Use the playwright-test-planner agent to create a test plan for the
> inventory page (sorting, stock states, cart badge). Save it to
> `specs/inventory.md`.

Watch what it does: `planner_setup_page`, live browsing, then a structured
Markdown plan. Read the plan critically - would a new joiner reproduce the
tests from it?

## 2 · Generate

> Use the playwright-test-generator agent to implement `specs/inventory.md`
> as Playwright tests. Follow the house style in the skills and import test
> from tests/fixtures.

The generator verifies every locator against the live page as it writes
(`generator_setup_page`, `browser_*`, `generator_write_test`). Review the
diff like you would a human PR: locator quality, assertion strength,
`npm test` green.

## 3 · Heal

The suite is already broken (run `npm test` - `single-item-checkout` fails:
the app's checkout button used to be `checkout-btn` and is now `checkout`;
our spec still uses the old id):

> Use the playwright-test-healer agent to fix the failing test.

Watch it: `test_run` to reproduce, `test_debug` to pause at the failure with
a live browser, `browser_snapshot` to see reality, then a minimal edit.

**Discussion:** the healer fixed a *selector*. What should it do when an
*assertion* is wrong - say a cart badge asserted as `'4'` when the app now
shows `'2'`? Try it: change the badge assertion in
`two-item-checkout.spec.ts` to `'4'`, run the healer again, and judge its
answer. A good healer distinguishes "the test is stale" from "the app is
broken", and flags behaviour changes for human review instead of silently
rewriting expectations. Revert the experiment afterwards.

## Done when

- `specs/inventory.md` exists and reads like a real plan.
- The generated inventory specs pass alongside the rest of the suite.
- The healed checkout spec is green, and the fix is minimal (a locator, not
  a rewrite).
- `npm test` fully green, `npm run typecheck` clean.
