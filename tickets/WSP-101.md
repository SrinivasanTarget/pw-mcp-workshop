# WSP-101 - Login error handling for blocked and mistyped sign-ins

**Type:** Story
**Priority:** High
**Component:** Authentication

## Summary

Users who cannot sign in must always understand why. Today the login form
(`/login`) accepts a username and password; when sign-in fails, an error is
shown in the form (element tagged `data-test="login-error"`).

## Description

The store has a locked-out account state (used for abuse prevention) and the
usual wrong-credentials case. Both must present a clear, specific message and
keep the user on the login page. Test accounts: `locked_out_user` (locked) and
`standard_user` (active); the shared password is `workshop123`.

## Acceptance criteria

1. Signing in as `locked_out_user` with the correct password shows the error
   "Sorry, this user has been locked out." and the user stays on `/login`.
2. Signing in as `standard_user` with a wrong password shows the error
   "Username and password do not match any user in this service" and the user
   stays on `/login`.
3. After a failed attempt, correcting the credentials and signing in as
   `standard_user` / `workshop123` succeeds and lands on `/inventory`.
